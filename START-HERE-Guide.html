Set up the shop app for your uncle's shop

One-time setup. About 60 to 90 minutes. Follow the steps in order and tick each one off. Every step says what you should see when it worked.

Safe for Profit Maker. Nothing in this setup ever writes to or changes the Profit Maker data file. The shop computer only reads a copy of the file and sends numbers to the cloud. Profit Maker works exactly as before.

What you need

  • The shop computer where Profit Maker is installed, switched on, with internet.
  • An email address you can open (Gmail is fine). Use the shop owner's email, so the accounts belong to him.
  • This kit folder (the zip you received). Unzip it. Inside you will see: 1-Database, 2-Website, 3-Shop-PC and this guide.
  • Three free accounts, made in the steps below: Supabase (database), GitHub (keeps the website files), Vercel (puts the website online). All three are free for a shop this size.
  • A notepad (paper or a text file) to write down passwords and keys. You will need them again.
Check first: the shop's Profit Maker must save its data in files named like Data2627.Mdb (the same version you use). If the files look different, stop and ask before continuing.

How it works (one minute)

Profit Maker filecopyShop computer (ShopSync)every 30 minSupabase (cloud database)readWebsite on VercelopenPhone app

The shop computer copies the Profit Maker file, reads the copy, and uploads the numbers to Supabase every 30 minutes. The phone app reads from Supabase. It also keeps its own records (staff, expenses, temporary bills, returns, collections, directory) in Supabase only.

Part A. Cloud database (Supabase)

1

Create the Supabase account and project

  1. Open supabase.com on the computer and click Start your project. Sign in with GitHub or with the email.
  2. Click New project. Pick the organization it offers.
  3. Name: for example uncle-shop. Database password: click Generate a password and write it down. Region: choose South Asia (Mumbai). Plan: Free.
  4. Click Create new project and wait 1 to 2 minutes until the project page opens.
2

Create all the tables (one file, one click)

  1. In the left menu click SQL Editor, then New query (or the +).
  2. On your computer open the folder 1-Database and open 1-setup-new-shop.sql with Notepad. Press Ctrl+A (select all), then Ctrl+C (copy).
  3. Click in the big Supabase text box, press Ctrl+V to paste, then click Run (bottom right). Then do the same, one file at a time and in order, for 2-migration-23.sql, 3-migration-24.sql, 4-migration-25.sql, 5-migration-26.sql, 6-migration-27.sql, 7-migration-28.sql, 8-migration-30-roles.sql, 9-migration-31-cash-slips.sql and 10-migration-32-deliveries.sql, 11-grants-new-projects.sql (new Supabase projects need it, otherwise the app shows "permission denied for table parties") and, last of all, 12-migration-33-attendance-times.sql (arrival and leaving times). Each one should say Success. (Push notifications are optional: see the 4-Push-Notifications folder.)
You should see: "Success. No rows returned". That is all. There is nothing else to run, no other SQL files.
If Supabase shows a yellow warning about "destructive operations" or "row level security", it is a normal prompt. Click Run this query. The file never deletes anything.
3

Create the login for the app

  1. Left menu: Authentication, then Users, then Add user and Create new user.
  2. Type an email and a password (this is what your uncle will use to open the app). Write both down.
  3. Tick "Auto Confirm User" and click Create user.
Important, do this now: go back to the SQL Editor, click New query, paste the line below and click Run. It makes the login an owner (without it the app opens empty). If you created the login before running the SQL files in step 2, you can skip this.
insert into app_roles (email, role) select lower(email), 'owner' from auth.users where email is not null on conflict (email) do nothing;
Owners and employees: create ONLY the owner logins now (before the SQL files, or run the owner line above). Create the employee logins afterwards; they get no access until you link them in the app: Staff > open or add the employee > type the same email in Login email > Save. To give one person extra rights also tick Desk login (mark attendance for everyone, assign deliveries, handle reports, returns and tasks, view expenses and the activity log) or Accountant login (receivables only, with PDF sharing) there. Run 8-migration-30-roles.sql first. A Desk login can also make a cash slip (it goes to an owner for approval, under Temporary bill > To approve) and browse stock without cost prices; this needs 9-migration-31-cash-slips.sql. The Desk also sends bills out with an employee (customer and products, no amounts), and employees see their own bills: 10-migration-32-deliveries.sql.
Tip: you can make a second login the same way for a staff member who should see the app too.
4

Stop strangers from creating accounts

  1. Left menu: Authentication, then Sign In / Providers (older versions: Providers or Settings).
  2. Find "Allow new users to sign up" and turn it off. Click Save.

The menu names change slightly between Supabase versions. You are looking for the sign-ups switch.

5

Copy the three codes

  1. Left menu: the gear icon (Project Settings), then API Keys (or API).
  2. Project URL is shown at the top (or under Data API). Copy it and paste it into your notepad.
  3. Copy the Publishable key (if you only see "anon public", that is the same thing) into the notepad.
  4. Copy the Secret key (click Reveal; if you only see "service_role", that is the same thing) into the notepad. Mark it SECRET.
Never paste the secret key into Vercel or GitHub. It is for the shop computer only.

Part B. The phone website (GitHub and Vercel)

6

Put the website files on GitHub

  1. Go to github.com and create a free account (use the shop email). Verify the email.
  2. Click the + at the top right, then New repository. Name it shop-app. Choose Private. Click Create repository.
  3. On the next page click uploading an existing file.
  4. On your computer open the folder 2-Website. Press Ctrl+A to select everything inside it (the files package.json, index.html, vite.config.js and the folders src and public) and drag them into the GitHub page.
  5. Wait until the upload bar finishes. Scroll down and click Commit changes.
You should see: in the repository list, package.json and the folders src and public directly at the top level. If you only see one folder called 2-Website, you dragged the folder itself. Delete the repository (Settings, bottom) and do it again with the contents.
7

Put the website online with Vercel

  1. Go to vercel.com, click Sign Up, choose Continue with GitHub. Choose the free Hobby plan.
  2. Click Add New, then Project. Next to shop-app click Import.
  3. Do not change the framework (it should say Vite). Open Environment Variables and add these, one by one (Name on the left, Value on the right, click Add after each):
NameValue
VITE_SUPABASE_URLyour Project URL
VITE_SUPABASE_ANON_KEYyour Publishable key
VITE_APP_NAMEshort name, 5 letters or fewer shows best, e.g. RAVI
VITE_SHOP_NAMEfull shop name, e.g. Ravi Medical Agency
VITE_GSTINthe shop's GST number
VITE_SHOP_ADDR1address line 1 (printed on bill copies)
VITE_SHOP_ADDR2address line 2, with town and PIN
VITE_SHOP_PHONEshop phone number
VITE_SHOP_DLdrug licence numbers, separated by |, e.g. 20B:TS/123|21B:TS/124
VITE_SHOP_BANKbank details line (optional)
VITE_SHOP_JURIStown for "Subject to ... jurisdiction"
  1. Click Deploy. Wait 1 to 2 minutes until you see confetti or "Congratulations".
  2. Click the preview picture or Visit. Copy the website address (for example shop-app-xyz.vercel.app) into your notepad.
If you add or change a variable later, you must click Redeploy (Deployments tab, three dots on the newest one) for it to take effect.
8

Test the website and put it on the phone

  1. Open the website address. You should see a login screen with the shop name. Log in with the email and password from step 3.
  2. You will see the app with no stock yet. That is correct. The data comes in Part C.
  3. On your uncle's phone open the address in Chrome (Android) or Safari (iPhone), log in, then menu, Add to Home screen. It now opens like a normal app.

Part C. The shop computer

9

Copy the ShopSync folder to the C: drive

  1. Copy the folder 3-Shop-PC\ShopSync from the kit to the shop computer (pen drive, or email the zip to yourself).
  2. Open This PC, open the C: drive, and paste the folder there. It must be exactly C:\ShopSync.
Not on the Desktop and not inside OneDrive or Documents. Those folders sync to the cloud and cause trouble. Use C:\ShopSync.
10

Run the setup

  1. Open C:\ShopSync and double-click START HERE - SETUP.bat.
  2. If a blue box says "Windows protected your PC": click More info, then Run anyway.
  3. A black window opens. It will ask for:
    • Supabase Project URL: paste it (right-click in the black window pastes).
    • Supabase secret key: paste the Secret key.
    • GSTIN: type the shop's GST number (this tells the app which state is "home", so other-state sales are shown as IGST). Press Enter.
    • It then searches the computer for the Profit Maker file. This can take a few minutes. If it shows several files, type the number of the current year (the one changed most recently) and press Enter.
  4. It makes a first backup, uploads the data (the first time takes a few minutes, it also loads the whole year's history), and sets up the automatic schedule.
  5. At the end you will see ALL DONE. Press Enter to close.
You should see: "Backup OK", "Upload OK" and "ALL DONE". There is a new folder ShopBackups (on D: or C:) with a zip file in it.
11

Check the phone app

  1. Open the app on the phone (pull down to refresh, or close and reopen it).
  2. You should now see the stock, the parties and the dues. Open Insights: it shows this year's sales and profit.
  3. Compare two numbers with Profit Maker: To receive total and the stock of one item. They should match.
The first full load can take up to 10 minutes. If Insights looks empty, wait and run run-sync.bat again.
12

(Optional) Load older years

To see last year in Trends and reports, double-click LOAD-OLD-YEAR.bat, drag an old file such as Data2526.Mdb into the black window, and press Enter. Do this once for each old year you want. It only reads the file.

The golden backup (do not skip)

Supabase's free plan does not keep backups. The golden backup is a single zip file with everything: all stock history, reports, and the app's own records (staff, expenses, directory, temporary bills, returns and collections, which exist nowhere else).

  1. Double-click run-golden-backup.bat once now. The zip appears in C:\ShopSync\golden.
  2. Once a week, copy the newest zip to a pen drive or Google Drive. The shop computer's own disk is not enough if it fails.
  3. To restore in an emergency: make a new Supabase project, run 1-setup-new-shop.sql and then migration files 2 to 8 again (step 2), create the login (step 3), put the new keys into Vercel (redeploy) and into sync-config.json, then double-click restore-golden.bat, drag the zip in and type YES. Finally run run-sync.bat.

When the new financial year starts (April)

Profit Maker creates a new file (for example Data2728.Mdb) in the same folder. The backup picks the highest-numbered file by itself, so you do nothing. After 1 April, run run-backup.bat and then run-sync.bat once and check that the app shows the new year. If it still shows the old year, send a photo of the black window.

Changing something in the app later

If you get an updated file for the website: on GitHub open the src folder, click Add file, Upload files, drag the new file in and commit. Vercel updates the website by itself in about a minute. On the phone, close and reopen the app to get it.

Keep these safe

  • Supabase email, password and database password
  • The app login email and password
  • The secret key (never share it)
  • GitHub and Vercel logins

Give your uncle a printed copy of this list, and keep one copy yourself.

If something goes wrong

What you seeWhat to do
Login says "Invalid login credentials"Wrong email or password, or "Auto Confirm User" was not ticked. In Supabase, Authentication, Users: delete the user and create it again with Auto Confirm ticked.
App opens but is empty after setupWait 10 minutes, then double-click run-sync.bat and read the last line. Reopen the app.
Black window says 401 or Invalid API keyThe secret key in C:\ShopSync\sync-config.json is wrong. Open it with Notepad, fix the key (keep the quotes), save, run run-sync.bat.
Error mentions column ... does not exist or relation ... does not existStep 2 was not completed. Open the SQL file again and run the whole file in Supabase.
"No Data*.zip found" or "No Data####.Mdb file found"Run run-backup.bat first. If it still fails, the data file location in sync-config.json (data_file) is wrong. Put the full path of the current Data....Mdb.
Cannot run scripts / red text about execution policyAlways start with the .bat files (double-click), not the .ps1 files.
App shows old numbersCheck the "last updated" line on the app's Home page. If it is old, run run-sync.bat. Then close and reopen the app.
Website shows a blank page or errorUsually a missing or wrong variable in Vercel (step 7). Fix it and click Redeploy.
Supabase says the project is "paused"Free projects pause after about a week without use. The 30-minute sync keeps it awake. If it happened, click Restore project and wait.
Asking for help: take a photo of the black window and send it with the files sync.log and auto-backup.log from C:\ShopSync. Never send the secret key.
